FocusGuard Prototype v2 · Philosophical theme

Philosophical prototype + full interaction logic for Codex.

This prototype uses a Bone White + Charcoal + Deep Sage theme to show the product philosophy, screen structure, and key flows for FocusGuard — an open-source attention firewall for reclaiming agency in the age of infinite feeds.

Prototype navigation
These views show the whole product logic, not just isolated visuals. Codex should use them as implementation guidance.

Core thesis

Modern apps removed stopping cues. FocusGuard puts them back.

Main differentiator

Block addictive surfaces like Shorts, Reels, Popular, and For You — without blocking the useful parts of apps.

Product language

Boundaries, Moment of Choice, Shared Boundaries, Attention Mirror, Chosen Windows.

Technical constraint

v1 should be Android-only, local-first, no backend, no account, bundled JSON rule packs, GitHub Releases + F-Droid.

Onboarding

Start by teaching the product philosophy. This is not “just a blocker.” It is an attention firewall that restores choice.

Technical Architecture
The v1 implementation should stay offline-first and avoid backend infrastructure.
v1 architecture
Android local-first

Kotlin + Jetpack Compose + Room + DataStore + bundled JSON rule packs. No server required.

App layer

Compose screens for Today, Boundaries, Moment of Choice, Attention Mirror, Shared Boundaries, and Settings.

Domain layer

BoundaryEngine, SurfaceMatcher, InterventionDecision, ChosenWindowChecker, ResetWindowManager, OverridePolicy.

Data layer

Room for boundaries and events. DataStore for preferences. Local JSON rule packs in assets.

System layer

UsageStatsManager for app-level usage. AccessibilityService only where necessary for surface detection and interventions.

Distribution

GitHub Releases APK first. F-Droid next. Google Play later after policy review.

Settings & privacy
Trust is product-critical. Local-first and transparent by design.
Local-first by default

Rules, moments, and reflection data stay on-device unless the user explicitly exports them.

No account required

No ads, no cloud requirement, no selling data, no default analytics.

Accessibility disclosure

Used only for minimal interaction detection and intervention logic. No message reading. No keystroke capture. No accessibility data upload.

Chosen Windows

Lunch window · Evening unwind · Temporary conscious override settings.

Interaction map
The full product logic should be understandable from this screen.
Flow A

Onboarding → permissions → install Shared Boundary pack → land on Today.

Flow B

Boundaries → choose app → choose surface → set action → save.

Flow C

Open high-risk surface → Moment of Choice → continue intentionally or leave → log event to Attention Mirror.

Flow D

Shared Boundaries → preview pack → install → adjust details.

End-to-end interaction logic

This map gives Codex a high-level understanding of how the product hangs together. The final app and Android implementation should reflect this architecture.

Philosophy layer Boundary layer Intervention layer Reflection layer Community layer
Step 1

Onboard

Teach the thesis, explain privacy, explain permissions, and frame FocusGuard as a humane tool rather than a control system.

Step 2

Choose boundaries

Create app-level and surface-level boundaries. Install a Shared Boundary pack or set up manually.

Step 3

Detect high-risk surface

Use Android monitoring + accessibility heuristics to detect the app and, where possible, the specific feed surface.

Step 4

Moment of Choice

Trigger warn / block / intent gate. Add humane friction and conscious override instead of shame.

Step 5

Reflect

Log the event locally, show patterns in Attention Mirror, and let the user refine boundaries over time.

Cost model

No backend

Bundle JSON packs, store data locally, publish APK through GitHub, target F-Droid, and delay Google Play until policy review.
